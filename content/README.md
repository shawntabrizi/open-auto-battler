# `@oab/content` — card and set registry (PolkaVM)

Holds the curated cards and card sets. A published card or set never changes
(`docs/CONTRACT_ARCHITECTURE.md` section 4.2).

- Cards are stored under their own id, once. Ids from `0x8000` are reserved
  for community cards (extension point only; `publishCard` rejects them).
- `publishSet` assigns the next set id (0, 1, 2, ...; decision Q11), pins the
  set by `keccak256(SCALE(SetBundle))`, and stores the set's **house ghosts**
  (decision Q1), pinned by `keccak256(SCALE(Vec<HouseGhost>))`.
- The deployer is the admin and the first curator. Only curators publish;
  only the admin adds or removes curators. There is no update or delete.
- pallet-revive stores at most **416 bytes per storage item**
  (`pallet_revive::limits::STORAGE_BYTES`). So every card, every house ghost,
  and the set's `CardSet` are separate items, and `getSetBundle` assembles the
  bundle from them. A `CardSet` must encode to 416 bytes or less (about 138
  cards).

Types (`oab-protocol`): `SetBundle { set_id, set: CardSet, cards: Vec<UnitCard> }`
(cards in order of first appearance in the set), `HouseGhost { round, board:
Vec<GhostBoardUnit> }`, `SetRecord { name, hash, ghosts_hash, publisher, block }`,
`CardMeta { publisher, block, origin: Curated | Community { creator } }`.

## ABI

| Function | Notes |
| --- | --- |
| `publishCard(bytes card)` | Curator. SCALE `UnitCard`. Reverts `CardExists(uint16)`, `ReservedCardId(uint16)`, `BadPayload()`, `NotCurator()` |
| `publishSet(string name, bytes cardSet, bytes houseGhosts) returns (uint16 setId, bytes32 setHash)` | Curator. SCALE `CardSet` and `Vec<HouseGhost>`. Every card must exist (`UnknownCard(uint16)`). Name 1–64 bytes; up to 64 ghosts, 1–5 units each, round > 0, set cards only (`BadHouseGhosts()`) |
| `setCurator(address who, bool allowed)` | Admin (`NotAdmin()`) |
| `getCard(uint16) view returns (bytes)` | SCALE `UnitCard` or empty |
| `getCardMeta(uint16) view returns (bytes)` | SCALE `CardMeta` or empty |
| `getSet(uint16) view returns (bytes)` | SCALE `CardSet` or empty |
| `getSetBundle(uint16) view returns (bytes)` | SCALE `SetBundle` or empty |
| `getSetRecord(uint16) view returns (bytes)` | SCALE `SetRecord` or empty |
| `getHouseGhosts(uint16) view returns (bytes)` | SCALE `Vec<HouseGhost>` (empty vector if none) |
| `setHash(uint16) view returns (bytes32)` | zero if absent |
| `setCount() view returns (uint16)` | set ids are `0..setCount()` |
| `isCurator(address) view returns (bool)`, `adminAddress() view returns (address)` | |

Events: `CardPublished(uint16 indexed cardId, address publisher)`,
`SetPublished(uint16 indexed setId, bytes32 setHash, bytes32 ghostsHash, address publisher)`,
`CuratorSet(address indexed who, bool allowed)`.

## Build and test

```bash
cd content && cargo build --release      # target/release/oab-content.polkavm (~42 KB) + .abi.json
# native tests, from the repo root:
CARGO_PVM_CONTRACT_INTERNAL=1 cargo test --manifest-path content/Cargo.toml --features std
```

## House ghosts

The starter list is generated by a fixed rule from the set's own cards
(`scripts/oab-plan/src/house_ghosts.rs`): rounds 1–10, three boards per
round (30 per set), `min(round, 5)` units drawn by rarity from cards whose
cost fits the round's mana limit, +1/+1 from round 6 and +2/+2 from round 9,
highest health in front. A designer can replace it with a hand-made list in a
new set.

## Deploy and publish (Paseo Next)

```bash
cd content && cdm deploy -n paseo && cdm i -n paseo @oab/content
cd ..   # repo root
cargo run -p oab-plan -- content /tmp/content-plan.json
(cd scripts && npm install)
OAB_SIGNER_MNEMONIC="<curator phrase>" node scripts/publish-content.mjs /tmp/content-plan.json <content address>
OAB_SIGNER_MNEMONIC="<curator phrase>" node scripts/publish-content.mjs /tmp/content-plan.json <content address> --verify-only
```

`publish-content.mjs` is idempotent. It dry-runs at the best block, checks
that `publishSet` would return the planned id and hash before it submits, and
compares every card, set, bundle, ghost list, and hash with the plan.
